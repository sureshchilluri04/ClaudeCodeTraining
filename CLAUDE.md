# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

Native Android app built with Kotlin and Jetpack Compose. Package/namespace: `com.example.claudecodetraining`. This is currently a freshly generated Android Studio "Empty Activity" project (single `MainActivity.kt` with a `Greeting` composable) with no additional architecture yet established — future work should establish conventions (navigation, state management, DI, etc.) as needed rather than assuming any exist.

## Build system

Gradle with Kotlin DSL (`.gradle.kts`), using version catalogs (`gradle/libs.versions.toml`) for dependency management. Single module: `:app`.

- compileSdk / minSdk / targetSdk: 36
- Kotlin: 2.0.21, AGP: 8.9.1
- Java compatibility: 11

## Common commands

Run all commands from the repository root using the Gradle wrapper.

```bash
# Build the debug APK
./gradlew assembleDebug

# Run unit tests (app/src/test)
./gradlew test

# Run a single unit test class
./gradlew test --tests "com.example.claudecodetraining.ExampleUnitTest"

# Run instrumented tests on a connected device/emulator (app/src/androidTest)
./gradlew connectedAndroidTest

# Lint
./gradlew lint

# Clean build outputs
./gradlew clean
```

## Architecture notes

- `app/src/main/java/com/example/claudecodetraining/MainActivity.kt` — single-activity entry point using Compose's `setContent`.
- `app/src/main/java/com/example/claudecodetraining/ui/theme/` — Compose theming (`Color.kt`, `Theme.kt`, `Type.kt`), following the standard Material3 theme scaffold generated by Android Studio.
- Unit tests live under `app/src/test`; instrumented (on-device) tests live under `app/src/androidTest`.
- The version catalog (`gradle/libs.versions.toml`) already declares dependencies not yet wired into `app/build.gradle.kts` (e.g. `navigation-compose-jvmstubs`, `kotlinx-serialization-json`, `datastore-preferences`, `navigation-runtime-android`), suggesting navigation, serialization, and DataStore are anticipated but not yet implemented. When adding these features, add the corresponding `implementation(libs.*)` entries to `app/build.gradle.kts`.
